# In This Town — procedural blocky shorts in JavaScript

This folder turns an episode script into a finished 9:16 short, with no Roblox assets and no
hand-made models. Characters, houses, trees, the sky ocean, whales, fish, jellyfish, the giant hands
and the eye are all generated by code with three.js. The music and sound effects are synthesized in
Python, so there is nothing to license.

Episode 6 output: `output/InThisTown_Episode06_OceanSky.mp4` (1080×1920, 30 fps, H.264 + AAC, about 61 s)
and `output/InThisTown_Episode06_OceanSky_thumbnail.jpg`.

## Pipeline

```
episodes/ep06_ocean_sky.json   script: voiceover lines, scene numbers, caption chunks and highlights
        │
tools/tts.py                   narration per line (Kokoro offline TTS, or ElevenLabs if a key is set)
        │                      → build/ep06/voice/*.wav + timeline.json (line, caption and scene timings)
render.js + web/               headless Chromium renders each frame as a pure function of time t
        │                      (deterministic, so frame ranges render in parallel workers)
tools/audio.py                 procedural score + SFX, timed from the same events, then mixed and ducked under the voice
        │
ffmpeg                         H.264/AAC MP4, loudness-normalised to −14 LUFS
```

Run everything:

```bash
npm install
PYTHON=/path/venv/bin/python ./make_episode.sh episodes/ep06_ocean_sky.json 3
```

Python packages: `kokoro-onnx soundfile scipy numpy`.

### Voices

Episode 6 uses ElevenLabs through OpenRouter (`"tts": "openrouter"` in the episode JSON). The API key is
sent as `Authorization: Bearer $OPENROUTER_API_KEY`; in Claude cloud sessions the network proxy injects it.

* Narrator: Antoni `ErXwobaYiN019PkySvjV` (American) on `elevenlabs/eleven-v3-conversational`, with the
  In This Town preset pitch 1.1 and tempo 1.12. The API ignores speed, so pitch and tempo are applied with
  ffmpeg afterwards: `asetrate=44100*p,aresample=44100,atempo=t/p`.
* Mom: `matilda`. Each line can set a delivery `tag` (for example `[whispers]`) and a `speak` text with pauses.
  Captions always use the script `text`.
* Pace: narrator lines with 3+ words aim for 2.8–3.0 words a second. A line outside that range gets up to
  3 takes, and a slow line may raise tempo to 1.15 and never more. Takes are cached in `build/tts_cache/`.
* Episode 6 averages 2.81 words a second. A Scribe transcript of the generated audio matched the script word for word.

Kokoro (offline) is still available with `TTS_BACKEND=kokoro`.

**Local narration when OpenRouter has no credit (Episode 21).** `tools/local_voice.py` makes every line with no paid voice: Silencio
(the video-farm's local TikTok-voice copies) speaks it, Seed-VC converts it onto clips of the series voices in `voice_samples/local_refs/`
(`ref_narrator.wav`, `ref_system.wav`), then the pace is set (2.9 words a second, tempo 1.0-1.15). It writes `build/<ep>/local_lines/` and
sets each spec line's `"audio"`, which `tts.py` then uses as it is; delete the `"audio"` keys to go back to ElevenLabs.

```bash
python tools/local_voice.py episodes/specs/ep21.json                  # all lines
python tools/local_voice.py episodes/specs/ep21.json --only 3,24      # remake some
python tools/local_voice.py episodes/specs/ep21.json --check          # faster-whisper transcript, WER per line and overall
```

* A word the converted voice keeps mangling ("Door" came out "Jawr") is fixed by another *source* voice for that line:
  `"local": {"src": "en_us_007"}` (Episode 21 tried five; splicing the word from another line was unintelligible). Spell numbers in `speak`.
* A child's voice: `en_us_006` with `"pitch": 1.28` and no conversion (the `boy` role).
* The converted lines haven't been judged by ear, only by transcript: say so in the manifest.
* A source voice too slow for the series pace (Episode 22: about 2.4 words a second at the 1.15 tempo cap): `"local_rate": 1.22` in the spec
  makes Silencio speak faster natively (`"local": {"rate": ...}` per line), so the tempo cap holds.

### Rendering on RunPod

`tools/runpod_render.py` rents a GPU pod at **$0.50/hr or less**. It reads live prices, requests only GPUs under
the cap, and deletes the pod if its actual rate is higher. The pod receives the code as a 42 KB bundle, finds a
hardware WebGL backend (EGL on NVIDIA), renders every frame and serves the encoded video on
`https://<podId>-8000.proxy.runpod.net`. The script downloads it and deletes the pod. If no GPU under the cap is
available, or the pod can't get hardware WebGL, `make_episode.sh` renders locally instead.
GPU and CPU frames are identical. Episode 6 rendered in minutes on an RTX 4000 Ada ($0.18–0.24/hr) instead of
about 25 minutes on a 4-core CPU.

A real avatar's textures may not fit on a pod: the bundle travels in an env var, and the pod API answers 500 with
`invalid character 'I'` at 1.25 MB (0.06 MB is fine). `launch` stops above 1 MB; render those episodes locally with
`node render.js frames <ep> 30 <start> <end> 1` in a few parallel workers.

### Mix

A cue can be a spoken sample: `["L24e+0.4", "sample", 0.5, {"name": "n_x", "rate": 0.93, "pan": -0.7, "rev": 2.6, "wet": 0.5}]` plays
`build/<id>/samples/n_x.wav`, made by the spec's `samples` block (`{"n_x": {"text": "Danielle. Danielle.", "voice": "names", "tag": "[whispers]"}}`).
Give a sample a few words: one whispered word with an ellipsis comes back 0.3 s long. `scratch` is a new effect too.
`tools/caption_sync.py episodes/epXX.json` moves caption chunks onto the spoken words (faster-whisper, local); run it after `tts.py`, before
frames. `tts.py` and `qc.py` read the OpenRouter key from the environment, then `~/.env`, and `qc.py` falls back to local faster-whisper
when Scribe can't run. If plain `python tools/audio2.py` fails on scipy, set `PYTHONPATH=D:/Claude/itt-renderer/.pylib`.

Every voice line is levelled to the same loudness. Music ducks up to 15 dB and effects up to 15 dB under speech
(30 ms attack, 350 ms release, 80 ms look-ahead). `tools/audio.py` prints each line's speech-to-background ratio
and flags anything under 10 dB. In Episode 6 the worst line is 11.9 dB.

To preview while editing, render a few stills at quarter resolution and put them on a contact sheet:

```bash
node render.js stills ep06 0.25 1 5 10 20 30 40 50 60
python3 tools/sheet.py build/ep06 build/ep06/sheet.jpg 1 5 10 20 30 40 50 60
```

## Engine (`web/engine/`)

| file | what it makes |
|---|---|
| `character.js` | R6-style blocky avatars (rounded boxes): clothing, hoodie, hair styles, canvas-drawn faces (wonder, curious, worried, scared, shock, calm, creepy…), poses (idle, look up, point, wave, run, scared, lean). |
| `town.js` | Pastel suburb (houses, roofs, windows, hedges, trees, streetlights, roads, town square, fountain, the warning sign). Static geometry is merged per material. Emma's house has a real two-storey interior with a staircase, window openings and lights. |
| `ocean.js` | The suspended ocean: a dense membrane shader with ripples, caustic light, colour grading, giant-hand indentation (a hand SDF shared with the hand meshes), glowing cracks (Voronoi), the hole and the eye, plus the sky dome. |
| `creatures.js` | Whales (lathe body, flapping flukes), instanced fish schools that can freeze in place, glowing jellyfish with light pools on the ground. |
| `core.js` | Shared uniforms and the world-space caustic patch applied to every outdoor material. |

`web/episodes/ep06.js` is the director: lighting palettes over time (day → night → evening → purple → red →
dread → crack), the shot list (camera paths keyed to narration lines), character blocking, captions and the
camera-shake and flash overlays.

## Production quality (every JavaScript video)

The user's standing rule (2026-11-06): every video from this renderer gets high-quality detailed models (buildings,

Episode 17 was made before the rule and stays as it is.

## Model library

One place for everything an episode can pull in by name: buildings, vehicles, props, accessories, environments and avatars.
**Check it before building something new, and add anything new when a video is done.**

```bash
python tools/models.py list            # everything, avatars included
python tools/models.py list vehicle    # one kind
python tools/models.py credits ep20    # the credit lines for the models an episode uses
node render.js stills library 0.5 0 1 2   # check page: still n shows model n
```

Using a model takes one line, and an episode loads and bundles only the names it uses:

```js
import { model } from '../engine/library.js';
const ctx = await initStage('ep20', { models: ['old_truck', 'farm_maya'] });   // files and avatars to load
const box = model('package_box', { parent: ctx.scene });       // a builder: its own options, see engine/models.js
const truck = model('old_truck', { parent: ctx.scene, height: 8 });   // a file: scaled to 8 studs high
```

The catalogue is `web/assets/models/index.json`. Models made in code are builders in `web/engine/models.js` (add one to `BUILD`,
and a line to the catalogue). Those from Episodes 7 to 16 are copies: the episodes keep their own code, so their renders can't
change. Episode 17 imports its package, model house and cardboard sky from the library. Model files are one `.glb` each in
`web/assets/models/<name>/`: GLB loads in one request and keeps the look of the source.

### Free models from other sites

Only when a story needs one; no bulk downloads. Add it with the licence recorded:

```bash
python tools/models.py add old_truck D:/downloads/old_truck/truck.glb --kind vehicle --desc "a rusty pickup" \
  --source "Poly Haven" --author "Name" --licence CC0 --url https://polyhaven.com/a/... --tris 30000 --tex 1024
```

`add` takes `.glb .gltf .fbx .obj` only, reads the file in a folder of its own with Blender's scripts off, reduces the polygons
and textures to the limits given, and refuses NonCommercial, NoDerivatives, editorial and unclear licences. Match the scene's
look, and keep real brand logos out of shot.

| Site | Licence | Stored in git? | Sign-in |
|---|---|---|---|
| Poly Haven | CC0, no credit needed; its page allows redistribution | yes | not stated on the licence page |
| Kenney | CC0, no credit needed; the page doesn't mention repositories, CC0 allows it. Tools can't fetch it: the user downloads the pack in their browser (robots.txt shuts out bots, and the download link answers 403 to a plain request, 2026-11-06) | yes | no account: "Continue without donating" |
| BlenderKit (now Blendkit) | per asset: CC0, or its Royalty Free licence (commercial use and animations allowed, no credit, no re-selling the model; blendkit.com/docs/licenses, read 2026-11-06). Free assets only | CC0 yes; Royalty Free: `--licence royalty-free --no-redistribute` | none for free assets |
| Quaternius | read the licence link on the site first (not verified, 2026-11-06) | if CC0 | check |
| Sketchfab | per model: read its page. CC0 and CC-BY only (`--licence CC-BY` needs `--author` and `--url`). Site terms not verified: the page didn't load, 2026-11-06 | CC0 / CC-BY yes; otherwise `--no-redistribute` | account |
| TurboSquid | royalty-free licence: video is a permitted use, but "giving away the 3D model file itself is not allowed" | no: `--licence royalty-free --no-redistribute` | account |

`--no-redistribute` keeps the file in `web/assets/models/local/`, which git ignores and pod bundles skip: it lives on this PC only,
so an episode using it renders here. Sites that need an account: the user signs in, Claude never creates one or enters a password.

Sketchfab goes through the `sketchfab` MCP server (`D:\Claude\sketchfab-mcp-server`), not the browser: `sketchfab-search` (CC0 and CC-BY by default), then `sketchfab-model-details` before each download to confirm the licence, then `sketchfab-download` into a new empty folder. Take `--licence`, `--author`, `--url` and the title from `sketchfab-model-details`, not search, whose links can be odd `none-<uid>` ones. Only a session started after the server's install has these tools.

BlenderKit goes through `tools/asset_fetch.py` in the video-farm repo (`D:\Claude\crash-sandbox`), or the `3d-assets` MCP server's `search_assets` / `get_asset` / `download_asset` in a session started after its install: `search "low poly tree" --cc0`, then `get <id>`, which saves the download and a `LICENCE.json` in `D:\Claude\3d-assets\<source>-<id>\` and prints the `models.py add` line with the licence, author and URL filled in. It takes free assets only and leaves paid and plan-only ones alone. A Kenney pack the user has downloaded goes in with its `record` command.

Every model with a CC-BY licence needs its credit line in the video's description: `python tools/models.py credits <ep>`.

## The pro look (every new episode)

Quality target: @zaylento.yt's level of detail, effects and post. New episodes call `initStage(ep, { look: 'pro' })`;
older episodes stay on `classic`, and `RENDER_LOOK=pro|classic` overrides either for a test.

- `engine/look.js`: ambient occlusion, sky-coloured environment light, ground bounce, soft shadows, neutral tone mapping,
  a final grade (`GRADE`; a palette can set `saturation`, `contrast`, `clarity`, `envI`, `bounce`). No vignette.
- **Sub-frames**: `RENDER_SAMPLES=4` gives motion blur, softer sun shadows and cleaner edges. A frame must depend only on
  t, and shots need a `name` so a cut stays clean. `FPS=60 RENDER_SAMPLES=4 tools/produce_episode.sh ...` for a final.
- `engine/kit.js`: tiling surfaces (`surf('brick', colour)`), `Batch` (bevelled parts merged per material), `building`,
  `skyline`, `crowd`, `crate`, `barrel`, `lamp`, `sign`. Detail comes from layers: trims, frames, ledges, signs.
- `engine/atmos.js`: `dust`, `sparkles`, `shaft`, `flame`, `clouds`. Call `.update(t)` each frame.
- `engine/atmos.js` also has `leaves` (falling), `burst` (sparks from a point: `.fire(t0)`) and `vanisher(ch, colour)`: `.set(0..1)` turns
  a character into blocks of light. `kit.js` has the surfaces `grass` and `cobble`, `character.js` has `nameTag(ch, text)`.
- `engine/forest.js` (Episode 18): `treeShape` / `treeSet` (instanced trees with bark, rustling leaves, `.pose()` to lean them),
  `heroOak`, `mossPad`, carved glowing names (`nameAtlas`, `namePatches`, `heroPatch`: a name that can be scratched or redrawn) and
  `leafLight(centre, radius, colour, i)`: a wave of coloured light through every crown (it darkens the leaf too, so green plus pink
  doesn't come out yellow).
- **Skin** keeps a little of its own colour on the pro look (`U.skinGlow`), so coloured light can't turn a face green or orange:
  no per-episode fix needed. Keep the sun and moon near neutral all the same: put the colour in the set, not the light.
- **Wide shots**: `frame(ctx, ..., { shadowSpan })` widens the sun's shadow map (studs either side of the focus).
- **Episode 18's lessons**: a dark forest needs far more fill than it looks (hemi ~2.2, amb 0.5, env 1.4, exposure 1.25), or trunks go
  black. Bark needs long vertical plates, or it reads as leopard spots under fill. A shot's end time must be finite: `ctx.dur + 1`, not
  999, or `u` stays near 0 and the camera never moves. On a curved trunk, size text by its letter advance or letters overlap, and leave
  the canvas room: a clipped digit looks like a crop. A caption sits at 1180 px: keep faces above it, by aiming the camera below the
  subject (aiming up moves things down the frame).
- **Extras**: crowds and unnamed characters may use `crowd()` or procedural bodies when that renders faster; named
  characters keep their cast model.
- `engine/home.js` (Episode 19): a modern home kit, in the library as `security_cam`, `home_fridge`, `dining_chair`, `dining_table`, `home_bed`,
  `home_sofa`, `potted_plant`, `pc_desk`, `selection_box` (Studio's blue outline) and `modern_house`.
- **Episode 19's lessons**: footage inside the story = a `ShaderPass` added last to the composer (mono, tear, blocks) plus a 2D HUD canvas placed after
  `ctx.grade`, and a `WebGLRenderTarget` of the same world for a monitor. The feed is linear and skips the tone map, so scale it down (x0.5). Infrared wants
  low point lights (70 near the lens, one per room): the first try at 420 blew every face out. Top-down shots need `steady: true`, or the noise drift tilts
  them. Check sightlines from a fixed camera with arithmetic before seating anyone. Cues with a built-in tail (`impact`, `sting`) crash under 2.4 s `dur`.
  The user wants no camera shake at the start of a story (2026-11-07): opening shots `steady: true`, `shake: 0`; shake only where a beat calls for it.
- **Episode 20's lessons** (`engine/isles.js`, the islands kit): a grid mesh built ring by ring needs its winding checked on the first still: the island's top was
  culled for a whole draft and the sea showed through, which read as "Kai is wading". If the ground looks like water, lower the sea in a debug still before
  touching colours. A held prop on `arms[1]` blocks the face from the +x side: orbit from `yaw - 0.4..0.6` and aim between head and hand. A portrait frame is
  only about `dist * tan(fov / 2) * 9 / 16` wide each side, so pull back rather than pan. A line can take a ready file with `"audio": "<wav>"` in the spec
  (`tts.py` decodes it instead of calling a voice): that is how narration carried on when OpenRouter ran out of credit (local Silencio + Seed-VC onto clips of the
  same voice). New moods in `audio2.py`: `fantasy` (harp arpeggio over strings), `ancient` (brass fifths, choir, timpani).
- **60 fps** from Episode 18: `FPS=60 RENDER_SAMPLES=4`, and `"fps": 60` in the spec so `qc.py` checks it. About 6 frames a second on the
  GTX 1060 with three workers (`node render.js frames epXX 60 <start> <end> 1`, one range each; existing frames are skipped, so a pass can
  stop and carry on). Run `tools/caption_sync.py` before frames: captions are in the frames. Clarity is clamped so it can't draw an outline
  round characters (the old hair halo).
- Check page: `node render.js stills lookdemo 1 0.5 2.5 3.5`. On Windows, render.js uses the NVIDIA card by itself.

## Real Roblox avatars

This is an alternative, not the default: the procedural blocky bodies stay the look of the series. An episode opts in
by using a `CAST` entry that names an avatar (`CAST.emily` is the first, Episode 17). Don't repoint existing entries.

Any cast member can be drawn with a real Roblox avatar instead of the procedural body. Download it once
on a machine that is signed in to Roblox, and every episode that uses that `CAST` entry picks it up:

```bash
export ROBLOSECURITY='<value of your .ROBLOSECURITY browser cookie>'   # an alt account is fine
python tools/roblox_avatar.py fetch ethan --user SomeUsername           # or --user-id 123, or --asset <id>
node render.js stills avatars 0.5 0.5 1.5 2.5 3.5 4.5 5.5               # check: real vs procedural, 6 poses
```

No cookie? In Roblox Studio, select the character Model, right-click > Export Selection > .obj, then
`python tools/roblox_avatar.py import ethan path/to/export/`.

### The farm library

Video-farm cast members are exported in bulk, with no clicks in Studio. Studio must be free; it comes to the front during capture:

```bash
python tools/farm_avatars.py all                    # the whole list in the script; finished characters are skipped
python tools/farm_avatars.py all --only maya,jake   # or any cast names
```

It captures 12 characters per throwaway scene, rebuilds them in Blender, bakes each with `tools/blender_avatar.py auto`,
imports it as `farm_<name>`, writes `web/engine/farm_cast.js` and tiles three poses of each into `build/roster/sheet_*.jpg`.
A failed character is recorded in `build/avatars/batch.json` and the run goes on; running it again retries what isn't done.

An episode names the avatars it uses, and only those load or go in a pod bundle:

```js
ctx = await initStage('ep20', { avatars: ['farm_maya', 'farm_john'] });
const maya = makeCharacter(farm('maya'));           // import { farm } from '../engine/farm_cast.js'
```

By hand, for one character (`auto` measures everything below; the options override it):

```bash
blender -b scene.blend --python tools/blender_avatar.py -- <character> <out dir> split:acc_Sweater=1.06 ...
python tools/roblox_avatar.py import farm_emma <out dir>
```

`tools/blender_avatar.py` bakes each part's colour to a JPG and names the groups like Roblox parts so they bind whole.
Options: `<part>=#rrggbb` (a skin-coloured cover), `split:<part>=<x>` (cut layered clothing at the shoulders),
`gain:<part>=r,g,b`, `fill:<name>=x,y0,y1,z,#rrggbb` (a filler slab for a gap). Check the six poses after every import.

* Files go to `web/assets/avatars/<key>/` (OBJ, MTL, textures, `avatar.json`) and `index.json`. Each
  `CAST` entry has `avatar: '<its name>'`, so fetching `ethan` replaces Ethan. Extras keep the procedural
  look unless their spec sets `avatar:`. `?avatars=0` on the page URL turns them all off.
* `web/engine/roblox.js` splits the mesh onto the procedural rig (hips, torso, neck, arms, legs), so
  `pose()`, walk/run cycles, head turns and props attached to `ch.neck` / `ch.torso` work unchanged.
  Body parts named like Roblox's (`Head`, `UpperTorso`, `LeftUpperArm`, `Left Leg`, ...) go to their bone
  whole. Hats and hair centred above the neck follow the head. Layered clothing and other accessories are
  cut per triangle at the shoulders, hips and neck.
* Limits: a real avatar keeps its own Roblox face unless its spec has `alti` (below);
  costume overrides in an episode (`{...CAST.x, shirt: ...}`) don't apply; R15 elbows and knees stay
  straight (the rig has one joint per limb). If a limb splits wrongly, set `landmarks`
  (`hipY`, `neckY`, `shoulderX`), `head_only` or `yaw` in `avatar.json`; the tool's docstring lists them.
* RunPod: avatars travel in the code bundle. Above 4 MB (`RUNPOD_MAX_BUNDLE_MB`) the launch refuses and
  `make_episode.sh` renders locally.
* Tested here on a synthetic R15 avatar in the 3D-thumbnail format (named parts, a hat, a backpack, a
  layered jacket, a textured face), through both the `fetch` save path and `import`. The live Roblox
  download itself is untested: Roblox's 3D endpoints need a signed-in cookie and aren't reachable from
  the cloud container.

### Animated Alti Wyre faces on real avatars (Episodes 18-26)

Main characters are real avatars with AltiWyre's cartoon faces: expressions, blinks and lip sync.

```js
ctx = await initStage('ep19', { look: 'pro', avatars: ['farm_daniel'] });
await loadAlti(['neutral', 'scared', 'shocked']);                       // every expression the episode uses, before makeCharacter
const ch = makeCharacter({ avatar: 'farm_daniel', alti: true, skin: '#f2c79a', caustic: false });
ch.setFace('scared', { blink: blinkAt(t, 0.3), viseme: visemeAt(line.text, line.start, line.end, t), gaze: 'left' });   // each frame
```

- `engine/altiface.js`; images from `python tools/alti_pack.py` into `web/assets/faces/alti/` (git-ignored: this repo is public and the pack's terms say not to re-upload it, so run the tool once per checkout). Presets, whole faces (`setFace('dizzy')`) and the
  pick-from sheets are the video-farm's (`docs/faces/` there). Aliases: `smile`, `worried`, `curious`, `shock`, `panic`, `fear`, `frown`.
- The head's texture is replaced with plain `skin`, so no avatar face shows underneath, and the head is shaded as a smooth box because the
  default head's sculpted eye sockets showed as rings. Give `skin` the avatar's hand colour. The face is a sheet ray-cast onto the head
  (`alti: { y, size }` tunes it): it can't float or sink, and hair sits in front of it.
- **Choose hair that clears the forehead**: fringes hide the eyes (Episode 18's first six candidates mostly failed on this).
- Check page, every face close: `RENDER_QUERY=only=farm_daniel node render.js stills altifaces 0.5 0.5 1.5 2.5 3.5 4.5 6.5`
  (`mkdir -p build/altifaces/stills` first).

**Making a new main character** (about 10 minutes, Studio free): find items with `tools/cat_find.py` in the farm repo (classic shirts and pants
bake cleanest; `--shirts`, `--pants`, `--hair`), put them in a throwaway `scenes/sandbox/avcap_<x>.lua` as `{ id = "x", items = {...}, colors =
{ skin = ... }, anchored = true }` rows (farm_avatars.py's `scene_text` is the template; 12 candidates fit one scene), run sync, Play,
`still_capture.py`, `still_build.py`, then `blender_avatar.py ... auto` and `roblox_avatar.py import farm_<x>`. Compare the candidates on the
check page and delete the rejects. The items of each avatar are in its `avatar.json`. Name it `farm_...`: other names load in every episode.
Gotchas from Episode 21: give `blender_avatar.py` an **absolute** output path (a relative one bakes without textures: transparent bodies,
404s); captured avatars face 180°, so set `"yaw": 0` in the new `avatar.json`; a hoodie that bakes too dark or with short sleeves takes
`LeftLowerArm=#hex RightLowerArm=#hex gain:UpperTorso/LowerTorso/LeftUpperArm/RightUpperArm=r,g,b` on the bake line. Characters are big
in a 9:16 frame (about 38° across at fov 64): a two-shot needs them side-on to the camera and close together, cheated toward it.

## Season 2 (Episodes 7–16)

Every Season 2 episode is built the same way, with the same narrator (Antoni, In This Town preset) and the same caption style:

```
episodes/specs/epXX.json  → tools/mkep.py → episodes/epXX_*.json   (script, cast voices, highlight words, sound cues, metadata)
tools/tts.py              → narration + timeline (auto 2–4 word captions with yellow/red/cyan highlights)
web/episodes/epXX.js      → the director: world, characters, ~15–25 shots keyed to narration lines
tools/produce_episode.sh  → RunPod GPU render (≤ $2/hr, local fallback) → tools/audio2.py mix → thumbnail → MP4 → tools/qc.py
```

Shared engine additions: `web/engine/stage.js` (renderer, palettes, shots, captions, overlays), `sky.js`
(sun/moon/stars dome), `props.js` (giant eye, IK spider legs, signs, glow sprites), a world "dissolve" effect
in `core.js`, configurable town (`buildTown(scene, { sign, house, ground })`) and `pose(..., 'sit')`.
`tools/audio2.py` is a cue-driven designer (music moods plus about 30 synthesized SFX: ticks, creaks, glitches, bells,
train horns, water rush, shell screams, chorus voices) with voice-first ducking and a 10 dB voice-margin check.

Outputs are in `output/InThisTown_Season2_Episodes07-16/`: one MP4, thumbnail and `_info.md` per episode
(transcript, title, TikTok caption, hashtags, thumbnail recommendation, QC result), plus `manifest.json`.
